# ADR: Evidence-Aware Lexical Identity and Conservative Morphosyntactic Reconciliation

**Status:** Proposed
**Date:** 2026-09-25
**Decision owners:** LangReader Core / Vocabulary
**Affected areas:** lexical identity, document vocabulary indexing, vocabulary preparation, adaptive assessment, linguistic validation
**Suggested implementation version:** Vocabulary preparation algorithm v7
**Supersedes:** no prior ADR
**Related repository evidence:** `VocabularyLexicalItemID.swift`, `VocabularyLexicalReconciler.swift`, `VocabularyDocumentLemmaIndex.swift`, `AdaptiveVocabularyAssessment.swift`, `VocabularyPredictionAudit.swift`, `VocabularyLexicalPartitionEvaluator.swift`, `VocabularyPOSEvaluator.swift`, `vocabulary-pos-validation-report-v2.md`

**Implementation state:** the evidence model, reconciler, reconciled inventory projection, assessment isolation, and partition evaluator are implemented behind the experimental v7 path. Experimental v4-v6 are superseded pre-freeze protocols whose candidate/evidence semantics are incompatible with the current implementation. Production remains on v3 while representative validation and the release gates in this ADR remain incomplete.

---

# 1. Decision Summary

LangReader will preserve the existing concept of a resolved lexical item:

```text
language + lemma + part of speech + optional future sense
```

and will **not** redefine a POS-free `language + lemma` group as a vocabulary item.

Instead, LangReader will introduce a document-scoped, non-persisted **lexical anchor** that temporarily groups occurrences requiring reconciliation:

```text
occurrence
    ↓
lexical anchor
    ↓
occurrence-level linguistic evidence
    ↓
document-level reconciliation
    ↓
┌─────────────────┬──────────────────┬───────────────┐
│ resolved single │ resolved split   │ ambiguous /   │
│ lexical item    │ lexical items    │ unresolved    │
└─────────────────┴──────────────────┴───────────────┘
```

A resolved item continues to use:

```swift
VocabularyLexicalItemID(
    language: ...,
    lemma: ...,
    partOfSpeech: ...,
    senseKey: nil
)
```

The important architectural change is **when that identity becomes authoritative**.

Today the pipeline is approximately:

```text
token
→ lemma
→ POS classifier
→ VocabularyLexicalItemID
→ aggregate by that ID
→ assessment
```

The new pipeline will be:

```text
token
→ morphological / lexical evidence
→ provisional anchor
→ collect evidence across occurrences
→ conservative reconciliation
→ resolved lexical items OR explicit abstention
→ assessment policy appropriate to resolution quality
```

`NLTagger` becomes an evidence source rather than the authority that creates lexical identity.

`VocabularyLexicalItemID` remains the identity of a **resolved coarse lexical item**.

`VocabularyLexicalAnchorID` becomes a temporary reconciliation construct, not a claim that all occurrences sharing a lemma belong to one vocabulary item.

Uncertain cases will not be silently collapsed into one lexical item and will not be forcibly split into several items.

`senseKey` remains disabled.

# 2. Why the Previous Architecture Needs to Change

The current implementation makes a structurally consequential decision from a relatively weak classifier output.

In `VocabularyDocumentLemmaIndex.buildPage`, LangReader currently obtains an Apple Natural Language POS hypothesis, applies:

```swift
minimumLeadingProbability = 0.65
minimumMargin = 0.20
```

and then immediately creates:

```swift
VocabularyLexicalItemID(
    language: language.rawValue,
    lemma: matchedLemma,
    partOfSpeech: partOfSpeech
)
```

The resulting key is subsequently used as an aggregation boundary.

The later `VocabularyPartOfSpeechReconciliationPolicy` can repair some `.unknown` occurrences, but it operates **after confident occurrence-level classifications have already become lexical partitions**.

That means a POS error is not merely a mislabeled token.

It can become:

```text
classifier error
    ↓
wrong lexical partition
    ↓
wrong candidate population
    ↓
different difficulty population
    ↓
different adaptive question sequence
    ↓
different estimated knowledge
    ↓
different learning deck
```

This is already visible in LangReader's own adverse validation evidence.

`vocabulary-pos-validation-report-v2.md` reports 480 English/German cases with:

| Metric                          | Result |
| ------------------------------- | -----: |
| Raw mapped-POS accuracy         | 74.58% |
| Abstention                      |  9.58% |
| Final lexical-identity accuracy | 69.38% |
| English held-out final identity | 73.75% |
| German held-out final identity  | 65.62% |

The same validation showed large missing/extra identity sets and deck symmetric differences, including a changed first assessment question for German.

This evidence does **not** prove that POS should be removed from lexical identity.

It demonstrates that the current classifier-to-identity transition is too aggressive.

# 3. Research Findings

## 3.1 What should count as a vocabulary unit?

This is not merely a software-modeling question.

Vocabulary research has debated word forms, lemmas, flemmas, and word families because the chosen unit changes measured vocabulary size and what knowledge may legitimately be generalized.

Bauer and Nation's classic word-family framework explicitly bases family membership on regularity, frequency, productivity, and predictability rather than simple string similarity.

Gardner emphasizes that the definition of “word” has important consequences for corpus-based vocabulary research, specifically identifying morphological relationships, homonymy/polysemy, and multiword units as difficult boundaries.

More recent L2 vocabulary work has questioned broad word-family assumptions because knowledge of one member does not reliably establish knowledge of every related member. Stoeckel, McLean, and Nation identify overestimation caused by assuming that knowledge of one word-family member implies receptive knowledge of the rest.

Most importantly for LangReader, Masrai defines a lemma for L2 vocabulary measurement as a headword plus its inflected, irregular, and reduced forms **of the same part of speech**. For example, `develop`, `develops`, `developed`, and `developing` may belong to one lemma when they belong to the same POS.

### Architectural consequence

The following should **not** be LangReader's final lexical identity:

```text
en | record
```

if that representation silently implies that noun `record` and verb `record` represent the same learner knowledge.

The existing resolved representation:

```text
en | record | noun
en | record | verb
```

is conceptually sound.

What LangReader needs is a temporary structure that permits the software to reason about occurrences of `record` before it knows whether one or both lexical items are actually instantiated.

Therefore:

> `language + lemma` may be a reconciliation anchor, but it must not be called a lexeme, lemma knowledge unit, or vocabulary item.

# 4. Terminology

The following terminology is normative for this ADR.

## Surface form

The text actually appearing in the document.

Examples:

```text
records
recorded
Häuser
Folgen
```

## Lemma candidate

A proposed canonical dictionary form supported by linguistic evidence.

A lemma candidate is not automatically authoritative.

## Lexical anchor

A temporary, document-scoped grouping key used to collect potentially related occurrences for joint reconciliation.

Conceptually:

```text
language + trusted lemma candidate
```

or, if trustworthy lemma resolution is unavailable:

```text
language + exact case-sensitive surface
```

An anchor is **not** a vocabulary item.

## Morphological analysis

A hypothesis about one occurrence, potentially containing:

```text
lemma
POS
morphological features
source/provenance
source score
confidence class
```

## Resolved lexical item

A vocabulary unit for which LangReader has sufficient evidence to instantiate:

```text
VocabularyLexicalItemID
```

## Ambiguous anchor

An anchor for which meaningful conflicting analyses exist, but evidence is insufficient to produce a safe partition.

## Unresolved anchor

An anchor for which there is not enough reliable linguistic evidence even to make a meaningful lexical classification.

## Residual occurrence

An occurrence belonging to an anchor for which lexical children are known, but whose own assignment remains ambiguous.

Residual occurrences are not forcibly assigned.

# 5. Architectural Invariants

The implementation must preserve these invariants.

### I1. Lack of NLP capability may reduce recall, never invent linguistic certainty

If Apple NLP, a language model, or another evidence source is unavailable:

```text
less resolved information
```

is acceptable.

```text
false grouping or unsupported grammatical certainty
```

is not.

This extends the graceful-degradation invariant already established by LangReader.

### I2. Resolved lexical identity remains POS-bound

A resolved item continues to be identified by:

```text
language + lemma + POS
```

with `senseKey == nil`.

### I3. A lexical anchor is never persisted as though it were a resolved lexical identity

`anchorKey` and `lexicalKey` have different semantics.

They must not become interchangeable.

### I4. Uncertain evidence must have an explicit state

No algorithm may convert:

```text
“we do not know”
```

into:

```text
noun
```

or:

```text
one merged vocabulary item
```

merely because a downstream API requires a key.

### I5. A single weak occurrence must not create a new lexical partition

New lexical children require corroborating evidence.

### I6. Unknown occurrences may remain unassigned

A resolved noun/verb split does not require every occurrence to be forced into noun or verb.

### I7. User-owned occurrence identity remains stable

Existing source anchors, occurrence IDs, SRS state, questions, answers, and user-created vocabulary must not be destructively rewritten by a new NLP version.

### I8. Sense disambiguation remains out of scope

No `senseKey` is generated in this ADR.

### I9. Network availability must not be required for lexical correctness

Offline reading must remain correct-by-abstention.

A network dictionary response must not be the sole fact authorizing a permanent lexical split.

### I10. Language-specific linguistic behavior belongs behind language/evidence boundaries

Core owns reconciliation semantics.

Language packages/providers own language-specific evidence.

# 6. Why Explicit Abstention Is Necessary

This decision is supported by a long line of statistical work on classifiers with a reject option.

Chow formalized the recognition-error versus rejection trade-off: when classification uncertainty is high, rejecting a classification can have lower expected cost than forcing an answer.

El-Yaniv and Wiener formulate modern selective classification around the **risk–coverage trade-off**: a system can deliberately classify fewer instances in exchange for lower error on the instances where it does make a decision.

That maps unusually well to LangReader.

LangReader does not need to label every occurrence.

Its product objective is closer to:

> Make strong vocabulary-level claims only where the evidence is sufficiently reliable.

Therefore the linguistic subsystem should optimize:

```text
resolution quality × coverage
```

rather than ordinary forced-classification accuracy.

A 90% classifier that labels everything is not necessarily superior to a 99% reliable lexical resolver that leaves 25% of hard cases ambiguous.

For vocabulary identity, an explicit abstention state is a feature, not a failure mode.

# 7. False Split and False Merge Costs

The earlier architecture discussion emphasized false splits.

That was incomplete.

Both directions matter.

## False split

One true lexical item becomes several predicted items.

Example:

```text
book[noun]
       ↓ classifier noise
book[noun]
book[verb]
book[other]
```

Possible consequences:

* inflated candidate count;
* fragmented occurrence frequency;
* repeated vocabulary questions;
* duplicated learning cards;
* unstable difficulty estimates;
* fragmented knowledge history.

## False merge

Two true lexical items become one predicted item.

Example:

```text
record[noun] ┐
             ├→ record
record[verb] ┘
```

Possible consequences:

* knowledge of the noun is generalized to the verb;
* frequency evidence combines distinct lexical behavior;
* learner knowledge is overestimated;
* an unknown usage may not be taught.

This is particularly important because L2 word knowledge is not all-or-nothing.

Schmitt's longitudinal work found that learners frequently did not know every meaning sense or derivational form of otherwise known words, while later research distinguishes vocabulary size from depth of knowledge.

Therefore the correct policy is not:

```text
uncertain → merge
```

nor:

```text
uncertain → split
```

It is:

```text
uncertain → abstain
```

# 8. Mathematical Decision Model

Let:

```text
q = P(a genuine lexical split exists | observed evidence)
```

Let:

```text
C_FS = cost of false split
C_FM = cost of false merge
C_A  = cost of leaving the anchor ambiguous
```

If LangReader had only two actions:

```text
S = split
M = do not split
```

then expected losses are:

```text
R(S) = (1 - q) · C_FS
R(M) = q · C_FM
```

Splitting is preferred when:

```text
(1 - q) C_FS < q C_FM
```

which gives:

```text
q > C_FS / (C_FS + C_FM)
```

This is the ordinary cost-sensitive Bayesian decision boundary.

But LangReader has a third useful action:

```text
A = abstain / remain ambiguous
```

with:

```text
R(A) = C_A
```

The optimal decision is:

```text
argmin { R(S), R(M), R(A) }
```

This naturally produces two decision boundaries.

Split becomes preferable to abstention when:

```text
(1 - q) C_FS < C_A
```

or:

```text
q > 1 - C_A / C_FS
```

No-split becomes preferable to abstention when:

```text
q C_FM < C_A
```

or:

```text
q < C_A / C_FM
```

The middle region can therefore remain explicitly ambiguous.

Conceptually:

```text
0                                            1
|-----------------|----------------|----------|
    single/none       ambiguous          split
```

### Important restriction

LangReader does **not currently possess a calibrated value of `q`**.

Therefore this formula defines the architecture and future decision policy, not the v1 implementation.

The first implementation must not pretend that Apple's `0.82` hypothesis score means:

```text
P(correct POS) = 0.82
```

# 9. Classifier Scores Are Not Automatically Probabilities

Modern classifier confidence values are frequently miscalibrated.

Guo et al. demonstrate substantial calibration error in modern classifiers and show that post-hoc calibration can improve the correspondence between reported confidence and empirical correctness.

Kull et al. similarly study multiclass calibration and evaluate calibrated probabilities using log-loss, Brier score, and calibration-error measures.

The general forecasting literature also distinguishes **calibration** from sharpness and recommends proper scoring rules for evaluating probabilistic predictions.

Therefore:

> `NLTagger.tagHypotheses()` values are evidence scores unless LangReader has independently demonstrated their calibration for the relevant language, OS/runtime, and document distribution.

The current thresholds:

```text
leading >= 0.65
margin  >= 0.20
```

remain useful as an engineering heuristic.

They must not be described as a 65% correctness threshold.

---

# 10. Domain Shift Makes Fixed Confidence More Dangerous

POS and morphology performance is domain-sensitive.

One published evaluation of general-purpose POS taggers on clinical narratives found accuracy drops of approximately 8.5–15 percentage points when moving out of the original domain; domain adaptation recovered substantial performance.

LangReader documents have their own distribution shift:

```text
fiction
non-fiction
OCR text
PDF extraction artifacts
EPUB prose
DOCX prose
dialogue
technical writing
historical language
quoted foreign phrases
mixed-language passages
```

This means Universal Dependencies token fixtures are valuable engineering evidence but cannot by themselves establish release-quality lexical identity performance.

Representative reading-document validation is required.

# 11. POS and Lemma Should Ultimately Be Treated Jointly

The longer-term linguistic abstraction should not assume that lemma is known perfectly before POS is considered.

Morphological analyzers commonly return several analyses for one surface form, and contextual disambiguation then determines which analysis is appropriate.

Research on morphologically rich languages explicitly frames the problem as **joint lemma and POS disambiguation**. Hoya Quecedo et al. describe morphological analysis as producing multiple possible lemma/POS analyses which must be disambiguated from context.

Shen et al. likewise show that the correct morphological analysis can depend on surrounding context, including for Russian, Turkish, and Arabic.

Even Stanford's Stanza pipeline makes POS a dependency of its lemmatizer: the lemma processor uses both the surface text and `UPOS`.

Therefore the long-term conceptual type should be:

```text
MorphologicalAnalysis {
    lemma
    POS
    morphological features
    provenance
    evidence
}
```

rather than treating:

```text
lemma = truth
POS   = optional annotation
```

This ADR does not require a complete morphological analyzer in the first implementation, but the API must leave room for joint analyses.

# 12. Cross-Language Morphology Model

Universal Dependencies provides a useful conceptual separation:

```text
lemma
POS
morphological features
```

and uses a cross-linguistic POS inventory alongside language-sensitive morphological properties.

LangReader should follow the same broad architectural principle without coupling itself to UD as a runtime library.

The existing `VocabularyPartOfSpeech` can remain a coarse language-neutral category system.

Language-specific morphology should not be forced into POS.

Examples:

```text
German:
Case=Dat
Number=Plural
Gender=Fem
VerbForm=Part

Spanish:
Mood=Sub
Person=3
Number=Sing

Russian:
Case=Gen
Animacy=Anim
Gender=Masc

English:
Tense=Past
VerbForm=Part
Degree=Cmp
```

The exact feature enum is not required in the first PR.

The architecture must merely avoid making it impossible later.

# 13. Proposed Core Data Model

## 13.1 Keep `VocabularyLexicalItemID`

The current type remains conceptually valid:

```swift
package struct VocabularyLexicalItemID: Codable, Hashable, Sendable {
    package let language: String
    package let lemma: String
    package let partOfSpeech: VocabularyPartOfSpeech
    package let senseKey: String?
}
```

Its semantic contract changes slightly:

> A `VocabularyLexicalItemID` represents a **resolved** coarse lexical identity, not an arbitrary output of one classifier invocation.

That is an important contract strengthening.

---

## 13.2 Add `VocabularyLexicalAnchorID`

Conceptually:

```swift
package struct VocabularyLexicalAnchorID: Hashable, Sendable {
    package let language: String
    package let basis: Basis

    package enum Basis: Hashable, Sendable {
        case resolvedLemma(String)
        case exactSurface(String)
    }
}
```

The anchor has no POS.

But this does **not** mean POS has been removed from vocabulary identity.

It means:

```text
anchor = question being investigated
lexical item = resolved answer
```

### Case safety

The exact-surface fallback must remain case-sensitive.

For example:

```text
Folgen
folgen
```

must not be collapsed merely because a generic canonicalization function lowercases both.

A `.resolvedLemma` anchor may use a language-owned normalized lemma.

An `.exactSurface` anchor must preserve the current safe exact identity semantics.

# 14. Occurrence-Level Evidence

Introduce an internal occurrence analysis.

Conceptually:

```swift
package struct VocabularyOccurrenceAnalysis: Sendable {
    package let occurrenceID: VocabularyOccurrenceAnalysisID
    package let sourceRange: VocabularyDocumentSourceRange
    package let surface: String
    package let anchor: VocabularyLexicalAnchorID
    package let analyses: [VocabularyMorphologicalAnalysis]
}
```

And:

```swift
package struct VocabularyMorphologicalAnalysis: Sendable {
    package let lemma: String
    package let partOfSpeech: VocabularyPartOfSpeech
    package let features: [VocabularyMorphologicalFeature]
    package let source: VocabularyLinguisticEvidenceSource
    package let rawScore: Double?
    package let confidence: VocabularyEvidenceConfidence
}
```

The precise feature representation can initially be empty or reserved.

The important change is that:

```text
POS hypothesis
```

becomes evidence attached to an occurrence.

It does not become the occurrence's permanent vocabulary ID.

# 15. Evidence Providers

Two distinct provider roles should exist conceptually.

## Lexical/morphological candidate provider

Answers:

> Which analyses are linguistically possible or attested?

Examples may eventually include:

```text
ECDICT lexical metadata
local German lexicon
German flexion data
future French morphological lexicon
future Russian morphological analyzer
```

## Contextual disambiguation provider

Answers:

> Given this occurrence in this context, which analysis is supported?

Initially:

```text
Apple NaturalLanguage
```

Future implementations might use another local model.

### Important rule

Provider scores must not be naïvely multiplied as independent probabilities.

For example:

```text
Apple says noun 0.8
dictionary supports noun
```

does not justify:

```text
0.8 × dictionaryProbability
```

unless independence and calibration are actually modeled.

V1 uses evidence classes and deterministic corroboration.

A future learned reconciliation model may combine features once sufficient representative data exists.

# 16. Network Resources

Existing network-backed dictionaries can continue to enrich UI information.

However, this ADR makes a distinction between:

```text
user-facing enrichment
```

and:

```text
identity-authorizing evidence
```

A network response should not be the sole reason that a permanent lexical identity changes.

Otherwise the same document could produce different vocabulary identities depending on:

```text
network availability
dictionary availability
cache state
response version
remote edits
```

For the first implementation, only deterministic/versioned local evidence should authorize automatic POS splits.

Network dictionaries may later become a versioned evidence source if a migration and reproducibility policy is explicitly designed.

# 18. Current Deterministic Reconciliation Algorithm

The current reconciliation policy is deliberately deterministic and conservative. Its
diagnostics identify the implemented policy as `lexical-reconciliation-v3`; this
section describes the policy shape rather than the persisted preparation protocol
version.

The current dataset is not large or representative enough to justify training a sophisticated meta-classifier.

For each anchor:

### Step A — gather all occurrences

Example:

```text
record #1
record #2
recorded #3
record #4
...
```

### Step B — gather contextual analyses

For each occurrence, keep:

```text
top POS hypotheses
raw leading score
margin
lemma evidence
evidence provenance
```

### Step C — convert raw hypotheses into evidence classes

For example:

```text
strong
usable
insufficient
unavailable
```

The current `0.65 / 0.20` rule can initially serve as the boundary between `usable` and `insufficient`, but its numeric values remain subject to validation.

### Step D — determine POS support sets

For every candidate POS, compute:

```text
number of supporting occurrences
number of distinct supporting contexts
lexical/morphological attestation
contradictory evidence
```

### Step E — reconcile

The state machine should behave approximately as follows:

```text
No reliable POS evidence
    → unresolved

One supported POS
and no credible conflicting POS
and the single-resolution corroboration gate passes
    → resolvedSingle

Two or more credible POS populations
and every child passes the split-evidence gate
    → resolvedSplit

Conflicting POS evidence exists
but split evidence is insufficient
    → ambiguous
```

Critically:

```text
conflict + insufficient evidence
```

does **not** mean:

```text
choose the highest score
```

and does **not** mean:

```text
merge and pretend knowledge is shared
```

It means:

```text
ambiguous
```

Single-POS resolution needs its own corroboration gate. A supported POS may become authoritative only when at least one independently justified path is satisfied:

```text
A. at least two usable observations
   in at least two distinct contexts

OR

B. one strong contextual observation
   plus independent lexical/morphological attestation

OR

C. a language-specific deterministic morphology rule
   whose precision has independently passed its validation gate
```

Otherwise the anchor remains unresolved. In particular, one usable contextual classification must not authorize a lexical identity and then cause unavailable occurrences to inherit that POS.

The production V1 configuration starts with path A. The architecture supports B, and C remains disabled for every language until that language is explicitly marked validated.

---

# 19. Split-Evidence Gate

The exact final constants must be chosen from development evidence, not intuition.

Nevertheless, the implementation should enforce structural conditions.

A new POS child must not be created from one isolated, uncorroborated classification.

A resolved split should require all of:

```text
1. At least two distinct supported POS categories.

2. Each proposed child has independent contextual support.

3. Support is not entirely duplicated from the same repeated context.

4. The evidence passes an empirically selected selective-classification
   threshold.

5. Conflicting evidence is not stronger than the evidence supporting
   the proposed partition.

6. When available, deterministic lexical/morphological attestation is
   consistent with the proposed POS categories.
```

A starting development policy may require more than one independent occurrence per newly established child.

That number is an engineering prior, not an academic constant.

It must be tunable in Validation and frozen only after development evidence is reviewed.

---

# 20. Distinct Context Support

Twenty repetitions of exactly the same extraction artifact should not count as twenty independent confirmations.

The reconciler should eventually distinguish:

```text
occurrence count
```

from:

```text
independent contextual evidence count
```

A lightweight V1 approximation is sufficient.

For example, context evidence can be fingerprinted from a normalized local token window.

Repeated identical windows then contribute less than genuinely different syntactic contexts.

This avoids the false confidence:

```text
same OCR/template sentence repeated 30 times
→ 30 independent votes
```

The first implementation can use capped duplicate support rather than sophisticated clustering.

---

# 21. Residual Unassigned Occurrences

Suppose the document clearly establishes:

```text
record[noun]
record[verb]
```

but one occurrence has insufficient evidence.

The correct representation is:

```text
noun child:
    occurrence 1
    occurrence 4
    occurrence 7

verb child:
    occurrence 2
    occurrence 5

unassigned:
    occurrence 3
```

Do not do:

```text
0.51 noun → noun
```

merely to create a complete partition.

This is another application of selective classification.

# 22. Changes to `VocabularyDocumentLemmaIndex`

`VocabularyDocumentLemmaIndex` should remain the document-scoped immutable linguistic index.

Its responsibility changes from:

```text
classify occurrence
→ create lexical ID
→ aggregate
```

to:

```text
extract occurrence
→ gather evidence
→ anchor
→ reconcile
→ expose resolved summaries
```

The current direct creation of:

```swift
VocabularyLexicalItemID(...)
```

inside token enumeration should be removed from the identity-authoritative path.

The page index may still store compact intermediate evidence for performance.

Document-level reconciliation occurs after page evidence is available.

# 23. New Summary Model

`VocabularyDocumentLemmaSummary` is becoming semantically overloaded.

A future-compatible replacement or extension should distinguish resolution.

Conceptually:

```swift
package struct VocabularyDocumentLexicalSummary {
    package let anchorID: VocabularyLexicalAnchorID
    package let resolution: VocabularyLexicalResolutionState
    package let lexicalItemID: VocabularyLexicalItemID?
    package let assessmentPolicy: VocabularyAssessmentIdentityPolicy
    package let observedForms: [VocabularyDocumentObservedForm]
    package let occurrenceCount: Int
    package let representativeRange: VocabularyDocumentSourceRange
}
```

Do not necessarily rename the existing type in the first PR if doing so causes excessive churn.

Semantics matter more than names during the migration.

# 24. Assessment Integration

This is the part where abstention must continue beyond NLP.

If an ambiguous anchor is simply converted into:

```text
language + lemma + unknown
```

and fed into the Rasch model, LangReader has merely moved the same epistemic error.

The assessment layer must know the quality of lexical identity.

Introduce conceptually:

```swift
package enum VocabularyAssessmentIdentityPolicy: String, Codable, Sendable {
    case fullInference
    case directEvidenceOnly
}
```

## `fullInference`

Used for resolved lexical identities.

These candidates may:

```text
participate in ability estimation
receive inferred known probabilities
influence adaptive question selection
be generalized according to the assessment model
```

## `directEvidenceOnly`

Used for ambiguous/unresolved anchors.

These items may still be useful to the learner.

For example, LangReader can ask about a specific occurrence/context.

Direct-evidence units are occurrence-scoped. An ambiguous eight-occurrence anchor is represented as eight direct-evidence units for assessment semantics, rather than one candidate whose answer would generalize across all eight occurrences.

But the response must not silently establish:

```text
knowledge of every hidden lexical item under that anchor
```

nor should weak identity contribute strongly to latent ability calibration.

---

# 25. Why Assessment Must Distinguish Identity Quality

Consider:

```text
record[noun]
record[verb]
```

Suppose LangReader cannot safely distinguish them.

If the learner knows the noun but not the verb and LangReader asks:

```text
Do you know “record”?
```

a positive answer is not evidence that both are known.

This follows directly from L2 vocabulary research warning against overly broad grouping assumptions.

Therefore ambiguous items must not be treated as ordinary Rasch items with a clean one-dimensional knowledge state.

The statistically safer initial policy is:

```text
resolved identity
    → normal assessment inference

ambiguous/unresolved identity
    → direct evidence only / remain uncertain
```

---

# 26. Minimum Safe Assessment Behavior

If `directEvidenceOnly` integration is too large for the first implementation slice, the minimum acceptable interim behavior is:

```text
ambiguous/unresolved anchors
    must not contribute to theta calibration;

ambiguous/unresolved anchors
    must not be automatically classified as estimated-known;

they may remain uncertain or enter a conservative review pool.
```

This prevents identity uncertainty from being converted into confident learner-knowledge inference.

Starting with v5 and retained by the current v7 reconciled protocol, ordinary adaptive questioning is limited to `fullInference` candidates. `directEvidenceOnly` candidates remain conservatively uncertain and may enter the learning/review result as occurrence-scoped units. If direct evidence is restored or recorded through a diagnostic path, it updates only that direct unit and never theta.

Question budgets are inference budgets:

```text
minimum calibration count
maximum calibration count
tail-validation schedule
stopping calibration state
```

All of these count `fullInference` answers only. UI/research interaction counts may still count every interaction separately.

---

# 27. `VocabularyReaderPrior`

The existing `VocabularyReaderPrior` is a **language-level theta posterior**, not a per-lexeme knowledge store.

It therefore does not need the family/lexical fallback hierarchy previously proposed.

That earlier idea should **not** be implemented in this ADR.

The reader prior can continue to operate per language:

```text
language → theta posterior
```

provided ambiguous lexical candidates do not contaminate the evidence used to update that posterior.

Reader-prior eligibility therefore counts only verified evidence from `fullInference` candidates. Verified direct-only interactions may be retained for research, but they neither update theta nor make a theta posterior eligible sooner. A completed session with no inference-bearing answers does not contribute a reader-prior session.

---

# 28. `PersonalVocabularyProfile`

`PersonalVocabularyProfile` currently has different semantics and relatively simple lemma-oriented English tokenization.

It should not be silently redefined as part of this ADR.

This ADR requires only:

> Do not assume that `PersonalVocabularyProfile.lemma` and the new resolved lexical identity represent identical constructs.

Migration of personal exposure modeling to multilingual lexical identities should be a separate architectural decision.

# 29. Persistence Strategy

The repository architecture correctly prioritizes user-owned data compatibility.

Therefore this change uses an additive, staged persistence strategy.

## Phase 1

No database migration.

Run the new reconciliation in-memory for vocabulary preparation and validation.

Existing persisted records remain unchanged.

## Phase 2

When a new saved occurrence has a resolved identity:

```text
lexicalKey = resolved VocabularyLexicalItemID.canonicalKey
```

When identity is ambiguous/unresolved:

```text
do not manufacture a resolved lexicalKey
```

If the application later requires persistence of the provisional anchor, introduce a separately named field such as:

```text
lexicalAnchorKey
```

with explicitly non-authoritative semantics.

## Legacy keys

Existing `lexicalKey` values remain readable.

No background process should reinterpret them and rewrite user data merely because the NLP algorithm changed.

# 30. Preparation Algorithm Version

Changing candidate identity semantics affects:

```text
question IDs
candidate population
question ordering
assessment posterior
final selection
```

Therefore activation of the current reconciled behavior requires:

```swift
VocabularyPreparationSession.currentAlgorithmVersion = 7
```

During staged rollout, the experimental reconciled path uses algorithm version 7 while the default production path remains version 3. Experimental version 4 was assigned before the conservative single-resolution, occurrence-scoped direct-evidence, and inference-budget semantics were finalized. Version 5 still allowed a strong one-off conflicting POS to remain residual under a dominant single identity; version 6 made such credible conflict ambiguous while retaining weak/spurious one-off evidence as residual, but its occurrence-scoped direct-evidence keys still embedded renderer-specific UTF-16 offsets. Version 7 identifies those provisional units by stable occurrence order within each lexical anchor, so equivalent PDF/EPUB/DOCX text does not acquire different assessment candidate IDs solely because extraction whitespace shifts offsets. These changes alter candidate identity and theta evidence, so persisted v4-v6 sessions, reader priors, prediction audits, and research protocol records are intentionally incompatible with v7. `currentAlgorithmVersion` moves to 7 only when the release gates are satisfied and v7 becomes the default behavior.

Old sessions remain readable according to their recorded version.

A partially completed v3 session or superseded v4-v6 session must not silently
resume under current v7 reconciled candidate semantics.

---

# 31. Sense Disambiguation Remains Disabled

The current:

```swift
senseKey: String?
```

should remain reserved.

This is not merely an implementation convenience.

Word-sense boundaries themselves are difficult to define and evaluate. Work in lexical semantics has long documented the difficulty of assuming discrete, stable senses, while WSD remains a substantial contextual inference problem.

L2 learners also frequently have incomplete knowledge of a word's meaning senses.

Therefore LangReader should stabilize:

```text
surface
→ lemma
→ POS
```

before attempting:

```text
lemma + POS
→ sense
```

`VocabularySenseDisambiguating` remains an architectural seam only.

---

# 32. Validation Must Change From Classification to Partition Evaluation

Ordinary POS accuracy is not enough.

LangReader's actual problem is closer to:

> Given all occurrences in a document, did we partition them into the correct lexical units?

That is a clustering/partition problem.

Clustering research provides metrics designed specifically for comparing predicted and gold partitions. Amigó et al. analyze clustering evaluation measures against formal constraints and motivate B-cubed-style evaluation.

LangReader should add a lexical-partition evaluator.

---

# 33. B³ Metrics

For occurrence `i`, let:

```text
P(i) = predicted cluster containing i
G(i) = gold cluster containing i
```

Then:

```text
Precision_i = |P(i) ∩ G(i)| / |P(i)|
Recall_i    = |P(i) ∩ G(i)| / |G(i)|
```

Aggregate:

```text
B³ Precision = average_i Precision_i
B³ Recall    = average_i Recall_i
```

and:

```text
B³ F1 =
    2 · P · R
    ─────────
      P + R
```

Interpretation:

```text
false merging → damages precision
false splitting → damages recall
```

This makes the metric directly relevant to lexical grouping.

---

# 34. Do Not Hide Abstention Inside B³

A system could obtain artificially attractive clustering precision by refusing to resolve hard items.

Therefore every B³ result must be reported alongside:

```text
resolved occurrence coverage
resolved anchor coverage
ambiguous rate
unresolved rate
```

The primary view should be a **risk–coverage curve**:

```text
coverage ↑
error/risk ↑
```

This explicitly exposes the trade-off advocated by selective-classification research.

---

# 35. Additional Lexical Metrics

The validation report should include:

### Joint lemma+POS occurrence accuracy

When the system resolves an occurrence, is the complete coarse analysis correct?

### Split precision

Of all predicted multi-POS splits, how many correspond to a genuine gold split?

This is particularly important because a split changes the vocabulary population.

### False-split pair rate

For occurrence pairs belonging to one gold lexical item:

```text
fraction placed into different resolved lexical children
```

### False-merge pair rate

For occurrence pairs belonging to different gold lexical items:

```text
fraction placed into the same resolved lexical child
```

### Residual assignment accuracy

When the parent split is correct, how often are resolved occurrences assigned to the correct child?

### Ambiguous rate

How often does the reconciler correctly choose not to decide?

### Unresolved rate

How much coverage is lost because no useful evidence is available?

---

# 36. Downstream Product Metrics

Linguistic quality is necessary but insufficient.

The validation harness must continue to measure consequences in the actual adaptive system.

For gold versus predicted lexical partitions, compare:

```text
assessment candidate count
occurrence denominator
frequency distribution
first-question identity
first N question identities
theta posterior
coverage posterior
estimated-known set
selected learning deck
```

Add quantitative distribution distances where useful.

For theta posterior distributions `P` and `Q`, Jensen–Shannon divergence is preferable to raw key comparison because it remains finite and symmetric:

```text
M = (P + Q) / 2

JSD(P,Q) =
    1/2 KL(P || M)
  + 1/2 KL(Q || M)
```

The existing deck symmetric difference remains useful because it reflects a user-visible consequence.

---

# 37. Statistical Reporting

Release decisions must not be based solely on point estimates.

If:

```text
98 / 100 splits are correct
```

the reported precision is 98%, but uncertainty remains substantial.

Newcombe's comparison of proportion confidence intervals supports score/Wilson-style methods over naïve normal approximations for binomial proportions.

Therefore precision gates should report a Wilson 95% interval.

A release statement should look like:

```text
split precision = 98.4%
95% Wilson CI = [95.x%, 99.x%]
N = ...
```

rather than simply:

```text
split precision = 98.4%
```

Learner-knowledge calibration reporting must also distinguish identity quality. Brier/ECE-style metrics should be reported separately for:

```text
resolved / fullInference candidates
directEvidenceOnly candidates
overall product behavior
```

Otherwise increased abstention can look like worse learner-model calibration merely because intentionally unresolved items begin at conservative probability 0.5.

---

# 38. Proposed Initial Release Gate

The following is a **LangReader product-safety target**, not a universal academic threshold.

For automatic creation of a new POS split:

```text
point split precision >= 98%
AND
95% Wilson lower bound >= 95%
```

The purpose is to ensure that structurally consequential splits are based on much stronger evidence than ordinary token POS classification.

This will generally require **hundreds rather than dozens** of representative resolved split decisions before the lower confidence bound becomes convincing.

The threshold may be revised only through evidence about actual downstream costs.

It must not be weakened merely to obtain higher coverage.

---

# 39. Other Release Gates

Before enabling the new reconciler for production assessment:

```text
1. No known invariant violation where unavailable NLP creates a
   confident split.

2. Split precision passes the product-safety gate.

3. False-merge rate does not materially worsen relative to the
   appropriate baseline.

4. B³ precision/recall materially improve relative to current
   identity grouping at comparable coverage.

5. Held-out assessment instability decreases.

6. PDF/EPUB/DOCX extraction produces equivalent linguistic
   partitions for equivalent prose.

7. Graceful-degradation tests pass on supported macOS runtimes.

8. Performance remains inside vocabulary-preparation budgets.

9. Representative reading-document validation exists in addition
   to UD fixtures.
```

No single aggregate accuracy number can substitute for these gates.

---

It provides useful:

```

Conceptually:

      "goldPOS": "verb"
    }

```

The gold structure is the partition, not merely individual tags.

# 42. Development vs Held-Out Data

Threshold selection, rule changes, and calibration must use development data.

Held-out data must remain untouched until the policy is frozen.

If the held-out set is repeatedly inspected while changing the policy, it has become development data and must be replaced.

This is especially important because the existing sample sizes are not large.

# 43. Future Calibration

After representative evidence becomes sufficiently large, LangReader may introduce calibrated probabilities.

Possible flow:

```text
raw provider outputs
    ↓
feature vector
    ↓
language/runtime-specific calibration
    ↓
P(analysis correct)
    ↓
document-level split posterior
    ↓
cost-sensitive decision + abstention
```

Calibration should be evaluated using:

```text
reliability diagrams
Brier score
log-loss
calibration error
risk–coverage curves
```

A multiclass calibration approach such as temperature or Dirichlet calibration is academically plausible, but the implementation choice must follow the actual data volume and model behavior rather than being selected in advance.

### Explicit non-goal

Do not train a calibration model on the current 480-case fixture and ship it as universal truth.

That dataset is not representative enough.

---

# 44. Future Probabilistic Reconciler

The architecture should permit, but not initially require, a probabilistic latent-variable interpretation.

For occurrence `o`, let:

```text
Z_o = latent lexical/POS analysis
E_o = observed linguistic evidence
X_o = contextual features
```

A future contextual model estimates:

```text
P(Z_o | E_o, X_o, language, provider/runtime)
```

For anchor `a`, the model can derive a posterior over partitions:

```text
P(partition_a | all occurrence evidence)
```

and ultimately:

```text
P(genuine split | evidence)
```

That probability can feed the cost-sensitive decision rule in Section 8.

The production system should move to this only when empirical data justify the added complexity.

---

# 45. Why We Should Not Simply Raise the POS Threshold

Alternative:

```text
0.65 → 0.80
```

Rejected as the primary solution.

Reasons:

1. It still allows one token-level classifier result to define structural identity.
2. Raw model scores are not proven calibrated.
3. One threshold will behave differently across languages and runtimes.
4. It does not use corroborating occurrences.
5. It provides no explicit representation for conflict.
6. It does not solve lemma/POS joint ambiguity.
7. It does not tell assessment that identity itself is uncertain.

Higher thresholds may become one component of the reconciler, but not the architecture.

---

# 46. Why We Should Not Remove POS From Lexical Identity

Alternative:

```text
language + lemma
```

as permanent identity.

Rejected.

L2 vocabulary research commonly treats lemma membership as POS-bound, and broad grouping assumptions can overestimate learner knowledge.

The problem is premature POS commitment, not POS itself.

---

# 47. Why We Should Not Always Merge Ambiguous Occurrences

Rejected.

It converts uncertainty into false evidence of shared learner knowledge.

The learner may know:

```text
record[noun]
```

without knowing:

```text
record[verb]
```

or may know one usage/sense better than another.

Broad grouping is therefore not a neutral fallback.

---

# 48. Why We Should Not Trust Apple NaturalLanguage as Ground Truth

Rejected.

LangReader's own held-out evidence already demonstrates substantial errors.

Further, domain-shift research shows that general-purpose POS accuracy can change materially across text domains.

Apple NaturalLanguage remains useful because it is:

```text
native
fast
offline
available without heavyweight dependencies
contextual
```

It should remain an evidence provider.

It should not be the authority that defines vocabulary ontology.

---

# 49. Why We Should Not Replace It With an LLM Per Occurrence

Rejected.

This would introduce:

```text
latency
network dependency
cost
non-determinism
privacy concerns
model-version drift
poor offline behavior
difficult reproducibility
```

It would also fail to remove epistemic uncertainty; it would merely replace one fallible model with another.

An LLM may later be useful for explicit user-requested explanation.

It should not sit on the hot lexical-indexing path.

---

# 50. Why We Should Not Immediately Add a Heavy NLP Runtime

Rejected for this ADR.

A heavier morphology/POS system could improve certain languages, but choosing such a runtime is a separate language-provider decision.

The architecture should make it easy to add:

```text
TreeTagger
Stanza-derived models
spaCy-derived models
finite-state morphology
language-specific analyzers
```

without requiring any of them globally.

The first objective is to make LangReader correct **under uncertainty**.

Better language engines can then improve coverage rather than becoming prerequisites for correctness.

---

# 51. Why We Should Not Activate `senseKey`

Rejected.

The lemma/POS layer is not yet reliable enough, and word-sense boundaries introduce another major ambiguous inference problem.

Sense separation receives a future ADR after POS-level identity is validated.

---

# 52. Performance Requirements

Current document indexing already uses bounded concurrent workers.

The new architecture must preserve that design.

Per occurrence, store only compact evidence required for reconciliation:

```text
source range
surface reference/key
anchor
top-k POS hypotheses
lemma evidence
small provenance fields
```

Do not retain full duplicate contexts for every token.

For `N` occurrences and bounded `K` analyses per occurrence:

```text
evidence construction ≈ O(N · K)
anchor aggregation ≈ O(N)
```

with small `K`, normally 1–3.

Document reconciliation should therefore remain effectively linear.

---

# 53. Dictionary Performance

Local lexical attestation should be:

```text
batched
cached
lazy where possible
```

Never perform one network request per document occurrence.

A document containing 10,000 words should not create 10,000 dictionary queries.

Candidate attestation should be keyed by normalized lexical anchor:

```text
one lookup per distinct anchor
```

not per occurrence.

---

# 54. Concurrency and Cancellation

The existing index has:

```text
bounded worker count
priority/seed support
cancellation
no partial return after cancellation
```

All must remain.

Reconciliation begins only from a consistent evidence snapshot.

If indexing is cancelled:

```text
no partial lexical partition becomes authoritative
```

A seeded/visible-first index must produce the same final lexical resolution as a fresh complete index once both contain the same document content.

---

# 55. Format Independence

The linguistic layer must operate on normalized extracted prose, not renderer geometry.

The existing whitespace-normalization behavior should remain.

Equivalent text extracted from:

```text
PDF
EPUB
DOCX
```

must yield equivalent linguistic evidence and partitions, except where the underlying extracted text genuinely differs.

For v7, direct-evidence candidate identity is invariant to renderer geometry and whitespace when the normalized lexical-anchor occurrence sequence is preserved. It is deliberately not a claim of identity stability across insertion, removal, or reordering of earlier occurrences of the same anchor; those operations change the occurrence sequence and may therefore change later ordinal suffixes.

PDF line-wrap handling remains a preprocessing concern and must not become morphological evidence.

---

# 56. Observability

Every resolved split should be explainable in diagnostics.

A diagnostic structure should be able to report:

```text
anchor
number of occurrences
resolved state
children
supporting occurrence counts
residual count
providers used
raw score ranges
attestation sources
reconciler version
```

Example:

```text
anchor: en|lemma|record

resolution: resolvedSplit

noun:
  supporting contexts: 8
  strong contextual evidence: 7
  lexical attestation: yes

verb:
  supporting contexts: 5
  strong contextual evidence: 5
  lexical attestation: yes

residual:
  1

reconciler:
  lexical-reconciliation-v3
```

This diagnostic information belongs in development/research output, not necessarily the user UI.

---

# 57. Privacy

Lexical identity resolution should remain local.

No document text needs to leave the machine for the standard reconciliation pipeline.

If future telemetry is added, prefer aggregate non-content measures such as:

```text
resolution-state counts
split/ambiguous rates
runtime/provider version
performance timing
```

rather than raw document sentences.

Network dictionary lookups remain explicit application services and are not required for the identity pipeline.

# 59. Core Tests Required Before Integration

Required deterministic unit cases include:

### English noun/verb split

```text
"The record survived."
"Please record the result."
```

When both populations meet the gate:

```text
record|noun
record|verb
```

### One spurious classification

Mostly noun contexts plus one weak/spurious verb classification:

```text
must not automatically create record|verb
```

Expected:

```text
resolvedSingle
```

or:

```text

```

depending on conflict strength.

### Single-POS corroboration

One usable POS observation must not create a resolved lexical identity or assign unavailable sibling occurrences. Two usable observations from independent contexts may authorize `resolvedSingle`. A duplicated context does not count as independent corroboration.

Strong contextual evidence plus independent attestation may authorize a single identity. A deterministic morphology rule may do so only when its language-specific validation gate is explicitly enabled.

After a valid noun/verb split, an uncertain occurrence remains residual rather than being forced.

### German capitalization

```text

```

must preserve existing safe behavior.

### NLP degradation

`OtherWord`, identity lemma, or unavailable lexical model:

```text
cannot create a confident lexical split
```

### Duplicate contexts

Repeated identical context cannot manufacture independent split evidence.

### PDF line wrap

Existing dehyphenation/range behavior remains unchanged.

### Priority indexing

Seeded and complete indexes converge to the same resolution.

### Deterministic candidate IDs

Same document + same provider/reconciler versions produce the same resolved candidate population.

### Cancellation

Cancelled indexing cannot publish a partial partition.

# 60. Shadow Rollout

The safest deployment path is shadow evaluation.

## Phase 0 — Freeze baseline

Record current:

```text

lexical identity metrics
assessment consequences
performance
```

No behavior change.

## Phase 1 — Introduce evidence model

Add anchors, occurrence evidence, and reconciler.

## Phase 2 — Compare partitions

For the same documents, calculate:

```text

new partition
gold partition where available
```

Do not migrate persisted vocabulary.

Bump algorithm version in flagged sessions.

## Phase 4 — Add assessment uncertainty handling

Prevent ambiguous/unresolved identity from contaminating theta inference.

## Phase 5 — Representative validation

Run:

```text

adversarial fixtures
realistic prose fixtures
PDF/EPUB/DOCX parity
supported macOS runtimes
English

```

Phase 5: evaluator plus deterministic English/German reconciled PDF/EPUB/DOCX parity exist; representative multi-runtime and held-out evidence remains incomplete

# 62. Expected Consequences

## Positive

The new model:

* prevents one classifier invocation from immediately becoming vocabulary ontology;
* retains linguistically meaningful POS-specific lemma units;
* represents uncertainty honestly;
* reduces false split propagation;
* avoids fixing false splits by introducing systematic false merges;
* permits multiple evidence providers;
* behaves safely when Apple NLP degrades;
* creates a scalable multilingual boundary;
* makes validation correspond to actual product behavior;
* preserves offline-first architecture;
* leaves room for future probabilistic reconciliation;
* protects existing user data.

## Negative

The architecture introduces more states:

```text
resolved
ambiguous
unresolved
residual
```

and therefore more code.

Coverage may initially fall because LangReader will admit uncertainty that was previously hidden.

Some apparently simple vocabulary lists will contain fewer confidently inferred items.

Assessment needs an identity-quality concept.

Validation becomes more demanding.

These costs are intentional.

The previous simplicity was partly obtained by silently converting model uncertainty into domain truth.

---

# 63. What Success Looks Like

The objective is not:

```text
100% POS tagging
```

and not:

```text
100% of words receive a lexical ID
```

The desired property is:

> When LangReader claims that several occurrences are the same vocabulary item—or that one anchor contains several vocabulary items—that structural claim is highly reliable, and when evidence is insufficient the application remains useful without pretending certainty.

A successful architecture has this monotonic property:

```text
better language evidence
    → greater resolution coverage

worse/missing language evidence
    → more abstention

never:

worse evidence
    → invented certainty
```

That should become the core linguistic correctness principle of LangReader.

---

# 64. Final Decision

Adopt an **evidence-aware, selectively resolving lexical architecture**.

Specifically:

```text
1. Retain POS in resolved VocabularyLexicalItemID.

2. Add a POS-free lexical anchor strictly as a temporary
   reconciliation construct.

3. Record linguistic evidence at occurrence level.

4. Reconcile evidence at document/anchor level before creating
   authoritative lexical identities.

5. Introduce explicit resolved-single, resolved-split, ambiguous,
   and unresolved states.

6. Permit residual unassigned occurrences.

7. Treat Apple NaturalLanguage as an evidence source, not an
   ontology authority.

8. Do not assume raw classifier scores are calibrated
   probabilities.

9. Prevent ambiguous/unresolved identities from participating in
   ordinary learner-knowledge inference as though they were clean
   lexical items.

10. Keep senseKey disabled.

11. Validate partitions using risk–coverage, B³, false-split,
    false-merge, statistical intervals, and downstream assessment
    consequences.

12. Roll out in shadow mode before changing persisted or
    user-visible behavior.
```

This replaces the implicit rule:

```text
classifier output = lexical identity
```

with:

```text
linguistic evidence
        ↓
conservative reconciliation
        ↓
resolved identity OR explicit uncertainty
```

That is the architecture LangReader should build its multilingual vocabulary engine around.

**Gardner, D. (2007). *Validating the Construct of Word in Applied Corpus-based Vocabulary Research: A Critical Survey*. Applied Linguistics, 28(2), 241–265.** Discusses consequences of word-unit definitions, including morphology, homonymy/polysemy, and multiword expressions.

**Stoeckel, T., Ishii, T., & Bennett, P. (2020). *Is the Lemma More Appropriate than the Flemma as a Word Counting Unit?* Applied Linguistics, 41(4), 601–606.** Reviews evidence against overly broad grouping in L2 pedagogy and assessment.

**Stoeckel, T., McLean, S., & Nation, P. (2021). *Limitations of Size and Levels Tests of Written Receptive Vocabulary Knowledge*. Studies in Second Language Acquisition, 43(1), 181–203.** Identifies overestimation caused by inferring knowledge of a full word family from one member.

**Masrai, A. (2022). *The Development and Validation of a Lemma-Based Yes/No Vocabulary Size Test*.** Defines lemma grouping as headword plus inflected/irregular/reduced forms belonging to the same POS and provides empirical vocabulary-assessment motivation for lemma-level measurement.

**Schmitt, N. (1998). *Tracking the Incremental Acquisition of Second Language Vocabulary*. Language Learning, 48(2), 281–317.** Demonstrates incremental and incomplete knowledge of senses and derivational forms.

**Schmitt, N. (2014). *Size and Depth of Vocabulary Knowledge: What the Research Shows*. Language Learning, 64(4), 913–951.** Reviews the distinction and relationship between vocabulary size and depth.

**Hoya Quecedo, J. M., Koppatz, M. W., & Yangarber, R. (2020). *Neural Disambiguation of Lemma and Part of Speech in Morphologically Rich Languages*. LREC.** Treats lemma/POS as contextual morphological-disambiguation problems.

**Shen, Q., Clothiaux, D., Tagtow, E., Littell, P., & Dyer, C. (2016). *The Role of Context in Neural Morphological Disambiguation*. COLING.** Shows that surface forms can have multiple morphological analyses whose disambiguation depends on context and differs across languages.

**de Marneffe et al. (2021). *Universal Dependencies*. Computational Linguistics, 47(2), 255–308.** Provides a cross-linguistic separation of lemma, POS, and morphological features useful as a conceptual model for LangReader's language boundary.

**Chow, C. K. (1970). *On Optimum Recognition Error and Reject Tradeoff*. IEEE Transactions on Information Theory, 16(1), 41–46.** Establishes optimal rejection as a legitimate alternative to forced classification.

**El-Yaniv, R., & Wiener, Y. (2010). *On the Foundations of Noise-Free Selective Classification*. JMLR, 11, 1605–1641.** Formalizes the risk–coverage framework underlying LangReader's proposed abstention strategy.

**Guo, C., Pleiss, G., Sun, Y., & Weinberger, K. Q. (2017). *On Calibration of Modern Neural Networks*. ICML.** Demonstrates that classifier confidence and empirical correctness need not be calibrated.

**Kull, M. et al. (2019). *Beyond Temperature Scaling: Obtaining Well-Calibrated Multi-Class Probabilities with Dirichlet Calibration*. NeurIPS.** Provides multiclass calibration methods and evaluates calibration using Brier/log-loss and calibration measures.

**Amigó, E., Gonzalo, J., Artiles, J., & Verdejo, F. (2009). *A Comparison of Extrinsic Clustering Evaluation Metrics Based on Formal Constraints*. Information Retrieval, 12, 461–486.** Provides theoretical motivation for clustering/partition metrics such as B³.

**Newcombe, R. G. (1998). *Two-sided Confidence Intervals for the Single Proportion: Comparison of Seven Methods*. Statistics in Medicine, 17(8), 857–872.** Supports robust score/Wilson-style confidence reporting for proportions.

**Kilgarriff, A. (1997). *I Don't Believe in Word Senses*. Computers and the Humanities, 31, 91–113; Navigli, R. (2009). *Word Sense Disambiguation: A Survey*. ACM Computing Surveys, 41(2).** Illustrate why stable automatic sense-level identity should remain outside the present architecture.
